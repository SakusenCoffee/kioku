# Fixes log: running Anki desktop natively on iOS and Android

Every problem found while bringing the unmodified Anki desktop app (`aqt`) to
iOS (`ios/`) and native Android (`android/`), what caused it, and where the
fix lives. Newest at the bottom of each section. Add to this file whenever
something new is fixed.

Background: on these platforms `sys.platform` is `"ios"` / `"android"`, so
Anki takes its **Linux** code paths (`anki.utils.is_lin` is true). Most work;
the ones below assume a desktop OS (spawning processes, X11/D-Bus, system
libraries, a file manager, an unrestricted file system).

## Building

| Problem | Cause | Fix |
| --- | --- | --- |
| Qt download hangs forever | aqtinstall's default mirror (ftp.jaist.ac.jp) stalls | `QT_MIRROR` in `shared/versions.env` (Berkeley mirror) |
| iOS `qmake` fails with exit 127 | Qt's iOS `qmake` is a wrapper pointing at the build machine's path (`/Users/qt/work/install`) | `ios/tools/fetch_deps.sh` rewrites the wrappers and `target_qt.conf` to the downloaded macOS host Qt, on every run (the path breaks again if `deps/` moves) |
| No iOS Simulator builds on Apple silicon | Qt's prebuilt iOS libraries have only `arm64` (device) and `x86_64` (simulator) slices | Test on a device; `tools/run_device.sh` |
| PyQt6 fails to compile: DTLS, Vulkan, `QProcess` | Qt for iOS lacks them; PyQt's config tests can't run when cross-compiling | `--disabled-feature PyQt_DTLS/Process/Vulkan/XCB/Wayland` in `ios/tools/gen_pyqt.sh` |
| sip: `'QProcessEnvironment' is undefined` | PyQt 6.11 declares its comparison operators outside the `PyQt_Process` guard | `ios/patches/pyqt6-qprocess-guard.patch` |
| `no member named 'EnterEditFocus'` | dropped the `QT_KEYPAD_NAVIGATION` define from the generated `.pro` | keep every define from the `.pro` (`tools/gen_pyqt_cmake.py`) |
| pyo3: `attempted to link to Python shared library but config does not contain lib_name` | pyo3 wants to link libpython for iOS | config files in `ios/tools/pyo3/` with `suppress_build_script_link_lines=true`; the app links Python itself |
| orjson needs rustc 1.95 | newer than Anki's pinned toolchain | orjson builds with `+nightly` (`tools/build_rust.sh`) |
| `dyld: Library not loaded: @rpath/Python.framework` | no `LC_RPATH` | `LD_RUNPATH_SEARCH_PATHS=@executable_path/Frameworks` (CMakeLists) |
| `rsbridge and anki build hashes do not match` | rslib reads its build hash from `out/buildhash`, absent outside Anki's own build | `build_rust.sh` writes the release's commit hash (only when it changes, or the whole core rebuilds) |
| `sip module implements ABI v13.0 to v13.11 but … requires v13.13` | Anki pins PyQt6-sip 13.11; sip 6.17 generates ABI 13.13 | use PyQt6-sip 13.13 (`shared/versions.env`) |
| Several Rust static libraries in one binary | – | iOS: links fine (ld64 takes the first `rust_eh_personality`); Android: see below |
| Changing anything regenerated all PyQt sources (full rebuild) | – | `gen_pyqt.sh` skips when its inputs are unchanged |
| Android: `no member named 'use_system_logger' in 'PyConfig'` | Apple-only config field | removed; CPython 3.13+ on Android sends stdout/stderr to logcat by itself |
| Android: `duplicate symbol: rust_eh_personality` | each Rust staticlib carries its own std; lld (unlike Apple's ld64) rejects the one unmangled symbol they share | `-Wl,--allow-multiple-definition` (`android/CMakeLists.txt`); every copy behaves the same |
| Android: Gradle `Downloading … gradle-9.3.1-bin.zip failed: timeout` | Java connects over IPv6 first, which times out on some networks (curl works) | `JAVA_TOOL_OPTIONS=-Djava.net.preferIPv4Stack=true` in `android/tools/build.sh` |
| Android: `androidx.core:core:1.17.0 requires … compile against version 36` | Qt 6.11's template pulls androidx.core 1.17 | `QT_ANDROID_COMPILE_SDK_VERSION 36` (target SDK stays 35) |
| Android: `INSTALL_PARSE_FAILED_NO_CERTIFICATES` | Gradle's release APK is unsigned | `android/tools/build.sh` signs it with the debug key (`apksigner`) |
| Android: minimum SDK 24 not possible | Qt 6.11's prebuilt libQt6Core imports `getentropy@LIBC_P` (API 28) and API 26 functions | minSdk 28 (Android 9) |

## Runtime: Qt WebEngine replacement

Qt WebEngine (Chromium) cannot run on iOS and is not offered for Qt on
Android. `shared/python/PyQt6/QtWebEngine*.py` and `QtWebChannel.py` are
pure-Python stand-ins (`shared/python/kioku/webengine.py`) over the system web
view (`kioku_platform.WebView`: WKWebView on iOS, android.webkit.WebView on
Android).

| Problem | Cause | Fix |
| --- | --- | --- |
| `pycmd()` / web channel | no `qt.webChannelTransport` | `webscripts.PRELUDE` defines a `QWebChannel` whose calls go to Python through each backend's `__kiokuNative` bridge |
| Pages laid out at 980 px and shrunk | Anki pages have no viewport meta | injected viewport meta (`webscripts.VIEWPORT`) |
| API calls rejected by Anki's media server | Qt's request interceptor adds an `Authorization` header; WebKit has none | headers from the page's interceptor are added to fetch/XHR to 127.0.0.1 by an injected script, and to the main request |
| `setFixedHeight(float)` TypeError (toolbar) | WebKit returns every JS number as a double, Qt WebEngine whole numbers as ints | `runJavaScript` results go through `_qt_value()` |
| rubicon: `No type encoding known for ctype ObjCBlock` | block parameters of `objc_method` need the raw type | declare them `c_void_p`, wrap with `ObjCBlock(objc_id(ptr), None, *types)` (WebKit's blocks carry no signature) |
| rubicon: `'ObjCBoundMethod' has no attribute 'ptr'`; setters silently ignored | rubicon only treats a name as a property if the runtime declares it; many UIKit getters come back as methods | `prop(obj, name)` for reads, explicit `setFoo_()` calls for writes |
| `desktop dialogs: QWebEngineView.focusProxy()` asserted non-None | WebEngine's view has a focus-proxy child | `focusProxy()` returns the view |
| Android: `pycmd is not defined`; links (`href="#"`) then open the server root (404 Not Found) | document-end scripts were wrapped in a function to wait for DOMContentLoaded, so Anki's bridge script's `var pycmd` became a local (indirect `eval` fixes that but the editor's CSP forbids eval and inline scripts: Browse/Add never got `domDone`, so closing them hung) | a document-start script calls `kiokuAndroid.documentReady()` on DOMContentLoaded; `KiokuBridge` then runs the main frame's document-end scripts with `evaluateJavascript` (top level, exempt from the page's CSP) |
| Android: `JSONDecodeError` on `webview.title`/`webview.url` | `JSONObject.wrap(String)` returns the bare string, not JSON | `KiokuBridge.call` quotes strings (`JSONObject.quote`) |
| Android: top bar sometimes half the screen tall after start-up | a `domDone` from the previous document reached Python after `setHtml` had started the next one, so Anki ran its queued JavaScript (the bar's height measurement) on the old page | every load bumps a per-view generation; the bridge script reads it (`kiokuAndroid.generation()`) when its document starts and sends it with each call; `KiokuBridge` marks calls from an older document `stale` and `kioku_platform.webview` answers them without passing them to Anki |
| AMBOSS: `QWebEngineProfile.__init__() got an unexpected keyword argument 'parent'`; its login then failed and closing the login window showed an error | the stand-in took positional arguments only, so the add-on's import stopped half way (its login dialog existed, the handler for its form did not) | `QWebEngineProfile(storageName, parent=…)` and `QWebEnginePage(profile=…, parent=…)` take keywords |
| AMBOSS side panel showed AMBOSS logged out; its back/forward buttons raised | no `cookieStore()` or `history()` (the lenient fallback returned `None`) | `QWebEngineCookieStore`: `setCookie` hands the cookie in Set-Cookie form to the platform jar (iOS `WKHTTPCookieStore`, Android `CookieManager`), `deleteAllCookies` deletes the cookies on the domains it set; `cookieAdded` fires for cookies set from Python only. `QWebEngineHistory` reads back/forward from the web view (`backForwardList`, `copyBackForwardList`) |

## Sync server and AnkiDroid's folder (Preferences › Advanced)

User guide: [sync-server.md](manual/src/features/sync-server.md). Code: `shared/python/kioku/`
`syncserver.py`, `ankidroid.py`, `advanced.py`; host tests in `shared/tests/`
(`shared/tests/run.sh`).

| Problem | Cause | Fix |
| --- | --- | --- |
| Anki's sync server can't be stopped or restarted inside the app | `syncserver()` in rsbridge runs until Ctrl+C, and only reads its settings once | `shared/patches/anki-syncserver.patch`: `BackgroundServer` (own thread and Tokio runtime, graceful stop with a 5 s limit for stalled clients, then the users' collections close) and `syncserver_start()`/`syncserver_stop()` in rsbridge; applied by both `fetch_deps.sh` |
| Android stops the process soon after Kioku leaves the screen | – | `KiokuSyncService`, a foreground service of type `specialUse` (no daily time limit, unlike `dataSync` on Android 15) while the server runs; its notification's Stop action stops the server |

| "sync status check failed: network error" at start-up; an automatic sync on open would fail too | the server started in the background after the main window had already opened the profile | the server starts before `AnkiQt.__init__` (binding takes milliseconds) |
| Changing the port before the server was ever on was refused ("password needs 8 characters") | no password yet | a password is made up when the tab opens, saved with the first change |
| A media folder outside the profile: card pages loaded images from the profile's own folder | `anki.collection` and `anki.media` each import `media_paths_from_col_path` by name; patching one left `col.media.dir()` (served to the web views) at the default | both are patched (`ankidroid.install`) |

## Remote desktop (Termux variant)

Guide and results: [termux/docs/remote-desktop.md](../termux/docs/remote-desktop.md).

| Problem | Cause | Fix |
| --- | --- | --- |
| x11vnc listened, then the first viewer got "connection closed" | `shmget: Permission denied`: Android has no SysV shared memory for apps, and x11vnc exits after binding its port | `-noshm`; start() also checks it still runs 2 s after listening |
| noVNC connected to its own page's port (`ws://host:6080/vnc.html`) | noVNC 1.7 uses a `port` setting only together with a `host`, and the host differs per connection | `ankidesk_novnc.py` makes `defaults.json` per request from the Host header; `/` opens `vnc.html` with the query kept |
| Back on the phone, Anki's window had the remote screen's size | Anki saves window sizes in the profile under one key per window | on the remote screen, `launch_anki.py` prefixes Anki's state keys with `kioku_remote_`; the first time there, Anki opens maximized |
| "Run without battery limits" still said "Recommended" after allowing it | the state file was written only at session start and Turn on | the bridge re-reads it every 2 s for a minute after opening Android's prompt |
| Power off didn't end the session (an existing bug) | Qt 6's `QApplication.quit()` is cancelled when a window refuses to close, and the desktop shell always refuses | `QApplication.exit(0)`; with the remote screen on, Anki there is closed first (the session's end gives it 3 s) |
