# Architecture

## One static wasm, like the iOS app

Kioku's iOS app links CPython, PyQt6, Qt and Anki's Rust core (`rsbridge`)
into one binary and registers the extension modules with
`PyImport_AppendInittab`. The web build does the same (`src/main.cpp`):

- **Emscripten 4.0.7**, because Qt 6.11's prebuilt WebAssembly libraries
  are built with it and static libraries should come from one toolchain.
  Pyodide is not used: Pyodide 314 needs Emscripten 5.0.3, and there is
  no PyQt for it.
- **CPython 3.14** built with CPython's own `Tools/wasm/emscripten`, with
  pthreads and without dynamic linking (`tools/build_python.sh`).
- **PyQt6** generated by sip-build against Qt for WebAssembly and turned
  into static libraries by Kioku's `shared/tools/gen_pyqt_cmake.py`
  (`tools/gen_pyqt.sh`).
- **rsbridge** as a Rust staticlib for `wasm32-unknown-emscripten`
  (`tools/build_rust.sh`).
- The Python standard library, Anki's packages and Kioku's Python are
  packed into `kioku.data` and appear under `/python`, `/site` and `/app`.

The shared `kioku` package (Kioku repo, `shared/python/kioku`) runs as on
the phones; `python/kioku_platform` is the web counterpart of
`ios/python/kioku_platform` and `android/python/kioku_platform`.

## Constraints that shaped the build

- **Threads.** Anki does collection work on threads, so Qt's
  `wasm_multithread` build and pthreads everywhere. Threads need
  SharedArrayBuffer, so the page must be cross-origin isolated
  (COOP/COEP headers, `tools/serve.py`). The pool of Web Workers is
  created up front (`QT_WASM_PTHREAD_POOL_SIZE` 32): Python's
  `Thread.start()` waits for the new thread, and on the main thread that
  deadlocks when a new Worker has to be started (it can only start once
  the main thread yields).
- **Blocking dialogs.** `QDialog.exec()` and other nested event loops need
  Asyncify (`-DKIOKU_ASYNCIFY=ON`, +60% wasm size). Asyncify can't unwind
  through JavaScript frames, so CPython is built without
  `PY_CALL_TRAMPOLINE` (its JS fallback trampoline sat on the stack). The
  stdlib, sip and pyo3 have worked with plain indirect calls so far. JSPI
  would be the modern replacement, but Qt only supports it when built from
  source.
- **Exceptions.** Rust on emscripten unwinds with wasm exception handling;
  the prebuilt Qt uses Emscripten's JS setjmp/longjmp, and the two can't be
  linked together. Rust is built with `panic=abort` (a panic ends the
  app). Qt built from source with `-feature-wasm-exceptions` would lift
  this.
- Rust's std is rebuilt with atomics (`-Zbuild-std`, nightly) for shared
  memory.

## Anki's web pages

Anki shows most of its UI in QtWebEngine pages served by a local web server
(`aqt.mediasrv`, Flask on waitress). Kioku replaces QtWebEngine with
`kioku.webengine`, a Python stand-in that drives a platform web view; on
the web that is an `<iframe>`.

### Web views (`python/kioku_platform/webview.py`, `shell/kioku-web.js`)

- Qt for WebAssembly wraps an HTML element given to `QWindow.fromWinId()`
  (the WId is a pointer to an `emscripten::val`, made by
  `_kioku_web.element_handle`) as a foreign window. Through
  `QWidget.createWindowContainer` Qt places, sizes and stacks it, so menus
  and dialogs cover the page as expected. It sets only the element's width;
  the height comes from the container's resize events.
- Qt embeds a placeholder `<div>`, not the iframe itself: an iframe loads
  only while it is in the document, and Anki keeps some views hidden until
  their page has loaded (`pycmd("domDone")`, e.g. the import page). Pages
  load in an off-screen parking spot and `adopt()` moves the iframe into
  the placeholder with `moveBefore()`, which keeps the page (Chrome 133+;
  elsewhere `appendChild` reloads it once).
- Every page gets `/_anki/__kioku/init.js`, which document.writes the
  view's scripts (`/_anki/__kioku/view/<id>/<gen>/<n>.js`): Kioku's bridge,
  `kioku.webscripts.PRELUDE`, Anki's own QWebEngineScripts. Each is its own
  file so it runs at global scope (Anki's bridge declares `var pycmd`);
  document-ready ones are added at DOMContentLoaded.
- The bridge (`bridge()` in kioku-web.js) defines `__kiokuNative` for the
  PRELUDE: channel calls (`pycmd`) and messages go to the parent page and
  into Python. `runJavaScript` results come back as events queued after
  whatever the script sent, because Anki's `saveNow()` expects the field
  saves first. Keys the page leaves alone (outside text fields, or with
  modifiers) are re-dispatched on Qt's window element, so Anki's shortcuts
  work as with QtWebEngine. Links to other origins go to Python
  (`acceptNavigationRequest`).

### Web server (`python/kioku_platform/http.py`, `shell/sw.js`)

A tab can't listen on a socket. The service worker catches `/_anki/`,
`/_addons/`, iframe navigations and every request made by a page in one of
the iframes, and posts them to the app page; the page passes them to wasm
(`kioku_post`), and Python hands them to a pool of worker threads that call
Anki's Flask app through its test client, as Anki's own server thread
would. `_kioku_web.respond` posts the answer back.

Anki builds `http://127.0.0.1:<port>/...` URLs (`mw.serverURL()`,
`webBundlePath`, its CSPs), but the page may be served from anywhere
(`127.0.0.1`, `localhost`, a domain), and only the page's own origin
reaches the service worker. `http.setup()` takes the page's origin
(`location.origin`): `serverURL()` and `webBundlePath` return it,
`getPort()` reports its port, and `127.0.0.1:<port>`/`localhost:<port>` in
CSPs, `Location` headers, text responses and `WebView.load_url()` become
it. Anki's Flask app itself still gets requests for `127.0.0.1`, which its
host check wants. Kioku's auth script (headers for Anki's API, added to
requests for host `127.0.0.1`) is pointed at the page's origin in
`WebView.set_user_scripts()`.

Responses are adapted for iframes in a cross-origin-isolated page:

- `Cross-Origin-Embedder-Policy` / `Cross-Origin-Resource-Policy` added;
- `frame-ancestors 'none'` (Anki forbids framing) becomes `'self'`;
- `'unsafe-eval'` is added where `script-src` is restricted (the editor,
  SvelteKit pages' meta CSP): `runJavaScript` from the outside counts as
  eval in the page;
- the init script is added to every HTML page; its `/_anki/` URL passes
  the editor's `script-src`.

### Page ↔ Python

- Python → page: `web.js(name, *args)` calls `__kiokuWeb.<name>` through
  `_kioku_web.run_script` (`emscripten_run_script_string`), main thread
  only.
- Page → Python: `__kiokuWeb.post(event)` calls the wasm export
  `kioku_post` from a fresh task (`setTimeout`), never while wasm is on the
  stack. `kioku_platform.web._post` queues HTTP requests for the server
  threads and hands everything else to Qt's event loop
  (`QTimer.singleShot(0)`), because handlers may open dialogs, which
  suspend the wasm stack.

### Files

`pick_files` opens an `<input type=file>` from the click that triggered it
and copies the files into the wasm file system (`/tmp/picked/…`) through
Emscripten's `FS`. `save_path` watches the export and downloads it once it
stops growing.

### Window

Qt for WebAssembly leaves the main window at its desktop size and Anki
restores the saved geometry when a profile opens, so the platform layer
keeps the main window fitted to the page (`_fill_screen`).

## Hosting (`cloudflare/`, `tools/dist.sh`)

The page needs COOP/COEP headers (GitHub Pages can't send them) and, for
sync and add-ons, the socket relay next to it. On Cloudflare Workers (free
plan) `build/dist` is served as static assets, and `cloudflare/worker.js`
runs first for every request:

- every response: COOP `same-origin` and COEP `credentialless`, or
  `require-corp` for WebKit (Safari, every iOS browser), which lacks
  `credentialless`; without isolation Emscripten's threads fail there
  (`DataCloneError`). With `require-corp` the service worker fetches
  cross-origin images and scripts with CORS (`shell/sw.js`). `tools/serve.py`
  does the same;

- `/kioku.wasm`, `/kioku.data`: Cloudflare takes files up to 25 MiB, so
  `tools/dist.sh` stores them brotli-compressed (17 MB and 5.5 MB) and the
  Worker serves them with `Content-Encoding: br` (`encodeBody: "manual"`);
  the browser undoes it. Content-Length is then the compressed size, so
  the page's download progress (`shell/app.html` counts the bodies as they
  arrive) takes the real sizes from `sizes.json`, written by `dist.sh`.
- `/__relay/<host>:<port>`: the same relay as `tools/serve.py`, with
  `connect()` from `cloudflare:sockets`. Anyone can send any `Origin`
  outside a browser, so on a public URL the host list (`RELAY_ALLOW` in
  `wrangler.jsonc`) is what keeps it from being an open proxy: AnkiWeb
  only by default, add-ons' services must be added.

## Development aids

- `__kiokuWeb.post({type: "devexec", code: "import aqt; result = aqt.mw.col.card_count()"})`
  in the page console runs Python in Kioku and prints `result`.
- `tools/test/boot.mjs` drives the app in headless Chrome (clicks, keys,
  uploads, screenshots, Python, the main thread's stack). Link with
  `--profiling-funcs` (on by default in `CMakeLists.txt`) for named wasm
  frames.
- `tools/link_core.sh` links CPython + rsbridge without Qt for node:
  seconds instead of minutes when working on the Python or Rust core.
